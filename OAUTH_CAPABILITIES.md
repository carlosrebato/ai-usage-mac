# OAuth capabilities and viability gate

AI Usage is an independent client and is not affiliated with Anthropic or
OpenAI. Provider usage endpoints used by the app are not documented for
third-party integrations and can change or be blocked.

## Claude

- Authorization client: the public Claude Code client identifier.
- Requested scope: profile only.
- Inference and API-key-creation permissions are explicitly forbidden.
- Called resource: the read-only OAuth usage-limit endpoint.

If a newly issued profile-only token cannot read limits, Claude direct support
fails the viability gate. The app must not widen its scope to make the request
work.

## Codex

- Authorization client: the public client identifier shipped by open-source
  Codex.
- Fixed effective scopes: `openid`, `profile`, `email`, `offline_access`,
  `api.connectors.read`, `api.connectors.invoke`.
- AI Usage calls only the ChatGPT usage-limit endpoint and does not invoke a
  model or connector.
- Mac fallback: documented `codex app-server` method
  `account/rateLimits/read`; the subprocess owns its credentials.

The Codex scopes are broader than the single operation AI Usage performs because
they are fixed by the borrowed public client. This is an accepted, documented
risk for the spike. A provider-owned client registration is the only clean way
to narrow them further.

## Claude macOS fallback

Claude can optionally read only the numeric
`~/.claude/ai-usage-rate-limits.json` artifact generated by
`Scripts/claude-statusline-ai-usage.mjs`. The helper receives Claude Code's
status-line payload on stdin, atomically writes a mode-`0600` file, and never
opens Claude Code's credential store.

Configure Claude Code's `statusLine` command to run:

```text
node /absolute/path/to/AI-Usage/Scripts/claude-statusline-ai-usage.mjs
```

Direct OAuth remains the primary source. This fallback is used only on macOS
and only after the user grants access to the selected Claude folder.

## Gate protocol

For each provider and device:

1. Sign in and verify current session/weekly limits.
2. Complete ten refresh rotations and concurrent-refresh tests.
3. Verify the official CLI/Desktop session remains valid.
4. Inspect a network capture for credentials outside the provider, analytics or
   project infrastructure.
5. Sign out and confirm the device Keychain item is removed.

No StoreKit, CloudKit or paid feature work is allowed until the direct flows and
the App Review spike pass.

## Signed safety switch

Release builds may set `AI_USAGE_REMOTE_CONFIG_URL` and
`AI_USAGE_REMOTE_CONFIG_PUBLIC_KEY`. The app accepts only a P-256 signed schema
containing disabled providers, a minimum version, a notice and validity dates.
It checks at most daily, retains only a verified cached policy and cannot change
an endpoint, scope or executable logic. Signing keys are not stored in this
repository.
